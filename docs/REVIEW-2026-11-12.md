## 2. Cross-cutting decisions for the main session

**D1. How to reset the demo story.**
- Recommend: one `resetStory(now)` function behind both a CLI and a token-guarded in-app route.
- Why: the CLI alone needs Andrew's laptop and .env.local, and a reseed is seconds of work. A shared function avoids two code paths.

**D2. What time the story happens.**
- Recommend: a lunch break with `{end}` templates (B2). Keep dumplings at +25.
- Why: starting dumplings at +15 (plan-time-there) would cut the stale slack from 16 to 6 minutes.

**D3. Realtime for locations.**
- Recommend: fan out on `user:<viewerId>`, not a `location:<id>` channel (map-03 proposed the latter).
- Why: fan-out leaks nothing to strangers, handles audience narrowing, and reuses the subscription each tab already has.

**D4. Location fuzzing.**
- Recommend: grid snap with no salt, `home: null` for non-self viewers, and venue quests showing the venue.
- Why: a salted hash (fbcore-02) is still a fixed per-user offset, so one leaked exact point reveals all later ones. Snapping a 2 km home cell (map-04) keeps a field no UI needs.

**D5. How Muse speaks in Messenger.**
- Recommend: a `sender` column with nullable from_id, not a Muse profile row (intros-03).
- Why: a profile row leaks into the switcher, search and suggestions unless every query filters it out.

**D6. Builder cap.**
- Problem: docs/PLAN.md already runs 6 M2b builders, against the rules' 3.
- Recommend: amend 20-workflow to "at most 6 in M2b, 3 otherwise", and split facebook into fb-feed, fb-people and fb-groups (fbcore-05).
- M4 becomes M4a/M4b: fb Messenger + MessageBubble export first, intros wiring after. 3D moves to M5.

**D7. Local friends on Alex's map.**
- Recommend: 4 visible local sharers plus 1 paused, all real Alex friends.
- Why: findmy-01 asked for at least 6 and demo-13 for fewer. Four keeps the "knows almost nobody" pitch and still fills the map.

**D8. Memories in the demo.**
- Recommend: use the seeded past crew on stage, and also allow any member to complete a quest.
- Why: completing on stage fakes the 25-minute wait.

**D9. Intro determinism.**
- Recommend: precompute with real Muse during reset; no hand-written score.
- Why: a canned 60 reads as a mockup, and live scoring takes too long on stage.

**D10. Intro meetups as 2-person quests.**
- Recommend: allow them, with an exception to the min-3 rule written into the 00-mission safety model (both opted in, trust path named, public venue).
- Why: this ties intros back into the loop.

**D11. Previews read dev, Production reads demo.**
- Recommend: yes.
- Why: milestone E2E would otherwise use up the demo seats.

**D12. Cut order if time runs out.**
- Cut first: 3D view, Reels, Daily Quest, Wrapped, Events detail, dating intros.
- Never cut: B1-B7, M1-M10.
